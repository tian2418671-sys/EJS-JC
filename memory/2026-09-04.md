# 2026-09-04 — 需求修正：导入方式从 ZIP 改为角色卡（PNG/JSON）

## 背景
- 用户明确指出：**导入对象不应该是 ZIP，而应该是 NPC 角色卡**——即酒馆/SillyTavern
  `chara_card_v2` 格式的 PNG 卡（tEXt `chara` chunk 内嵌 base64 JSON）和纯 JSON 卡。
- 用户提供真实示例卡「鬼 1.2版.png」验证解析（该卡自带错误点，是标准 `chara_card_v2`）。

## 交付内容
1. 新增 `mvu_lint/core/card_loader.py`：PNG/JSON 角色卡解析。
   - PNG：读 `tEXt chara` chunk → base64 解码 → JSON；JSON：直接解析。
   - 提取内容块：世界书条目 content、first_mes/description 等文本字段、
     regex_scripts、depth_prompt、tavern_helper scripts。
   - 内嵌「# 变量初始值」YAML 块解析为 schema dict（支持列表嵌套字典缩进）。
   - 支持写回：JSON 直接写，PNG 重建 tEXt chunk。
2. `project_scanner.py`：废弃 ZIP/目录扫描，改为 `scan_card()` 生成内容块索引。
3. `app_controller.py`：`import_card()` 替代 `import_zip()`（后者直接抛错拒绝）；
   schema 从卡内变量初始值提取；检查基于内存 content；自动修复写回角色卡。
4. UI/CLI：drop_zone 接受 .png/.json；main_window 文案与文件过滤器更新；
   `__main__.py` CLI 改为 `scan <角色卡.png|json>`。
5. 测试全部改写为 JSON 角色卡 fixture（82 passed）。

## 验证结果
- 示例卡「鬼 1.2版.png」：导入 143 个内容块（138 worldbook + 5 script）；
  变量初始值解析出 136 条 schema 路径；GUI e2e 全流程通过。
- 该卡当前 EJS 检查 0 错误：其 EJS 均为 `<%_ %>` 脚本标签 + `getvar()`，
  属 SPEC 2.1 静态子集边界外（只提示不报错）；无 `<%-`、无 `<!-- mvu:` 注释。

## 技术要点
- 变量初始值块按**内容前缀** `# 变量初始值` 检测（真实卡 comment 可能是 `[InitVar]请勿打开`）。
- YAML 子集解析器需处理「列表项后接更深缩进字段」（`- 姓名: x` + `性别: y` 同属一个字典项）。
- ZIP 相关代码全部移除；`import_zip` 保留为显式报错入口（防误用）。

## 下一步
- 若需对该类真实卡报错：扩展 EJS 解析器支持 `<%_ %>` 脚本标签、`getvar()` 引用提取。
