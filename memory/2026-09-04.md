# 2026-09-04 — EJS 解析器扩展：<%_ %> 脚本标签 + getvar() 引用提取

## 背景
- 真实卡「鬼 1.2版.png」的 EJS 全部是 `<%_ ... _%>` 脚本标签 + `getvar('stat_data.路径', {defaults})`，
  旧解析器 0 引用 0 错误（完全未覆盖），无法参与联动检查。

## 交付内容
1. `ejs_parser.py` 扩展：
   - 全局 `getvar('X.Y')` 引用提取（`_GETVAR_RE`）：覆盖输出标签、`<%_` 脚本标签、`@@if` 宏文本三种上下文。
   - getvar 路径前缀归一化：`stat_data./data./locals.` 剥除，与输出标签 `_DOTTED_ACCESS_RE` 行为一致，
     保证联动检查不误报（如 `getvar('stat_data.世界.当前幕')` → path `世界.当前幕`）。
   - `<%- getvar('...') %>` 内引用标记 `is_safe=False`，触发 Lv.4 未转义输出告警（`_UNSAFE_OUTPUT_TAG_RE` 范围判定）。
   - `EJSVariableReference` 新增 `source` 字段（output/scriptlet/macro/getvar），`to_dict` 同步。
   - 配对检查天然兼容 `<%_ ... _%>`（状态机按 `%>` 子串闭合）。
2. 测试：新增 6 项（scriptlet getvar、@@if 宏 getvar、未转义 getvar、无 getvar 脚本标签不产出引用、
   配对无错、双引号路径），88 passed（82 旧 + 6 新）。

## 验证结果
- 「鬼 1.2版.png」：12 个 getvar 引用全部提取（5 条唯一路径：世界.当前幕 / 世界.当前区域 /
  隐藏.人性残余 / 鬼魂.怨气 / 鬼魂.记忆），联动检查 0 误报 —— 该卡数据自洽（schema 136 条路径全覆盖）。
- 13 处 `getvar(` 中唯一未匹配的是文档说明文字里的 `getvar(`（后跟顿号非引号），属正确排除。

## 技术要点
- getvar 提取去重策略：输出标签正则先跳过 `getvar` 表达式（`_GETVAR_RE.match(expr)` 命中则 continue），
  统一交给全局扫描，避免同一调用被提两次。
- 前缀归一化必须与输出标签保持一致，否则 schema 联动全量误报（本次实际踩到并修复）。

# 2026-09-04 — 基于真实卡数据库的算法优化（14 张卡 + 2 份指导文件）

## 背景
- 用户提供 `数据库/`（14 张真实卡 PNG）+ `EJS实战指南_2025修正版.md` + `MVU_常见问题自查.md`，
  要求据此优化算法。先做全量语法形态普查（`scripts/scan_cards.py`）再动手。

## 三个高价值修复
1. **加载崩溃**：`extensions.tavern_helper` 可能是 `[["scripts",[...]],["variables",{}]]` 键值对列表
   （非 dict），`th.get("scripts")` 抛 `'list' object has no attribute 'get'` → 3 张卡无法导入。
   兼容 dict / 键值对列表，并对 character_book/regex_scripts 加防御。
2. **schema 提取泛化**：initvar 三种形态——`# 变量初始值`+YAML、`[InitVar]` 标签+纯 YAML/`---`、
   `[InitVar]`+内嵌 JSON（含 `$meta/$schema`）。按条目 label 识别，JSON 剥 `$meta`，跳过空占位块。
   修复前 14 卡仅 1 张有 schema，修复后 4 张。
3. **MVU `[值,说明]` 数组**：`[值, 说明]` 两元素数组是叶子变量（类型取第一元素），非普通 array；
   `getvar('stat_data.X.Y[0]')` 末尾 `[0]` 是取值访问器，剥掉匹配 schema `X.Y`，中间 `[N]` → `.N`。

- 真实卡端到端：BeiPaiDaoMu 91 getvar 全部联动通过；安达与岛村正确报 12 个 Lv.4；鬼1.2/星月 0 误报。
